# scaffold-native: both native projects, from the kit templates, running

Phase 2 starts here (guideline 01). The templates in `templates/native/` already follow the kit's architecture
(guideline 05), so the first slice starts from a building, tested app on both platforms, not an empty folder.

| | iOS (`templates/native/ios`) | Android (`templates/native/android`) |
|---|---|---|
| Project | XcodeGen `project.yml` (the `.xcodeproj` is generated and gitignored) | Gradle, version catalog, `build-logic` convention plugins (AGP 9, built-in Kotlin) |
| Modules | local package `Modules/`: CoreNetwork, CoreStorage, CoreDataLayer, CoreAnalytics, DesignSystem, FeatureHome | `:core:network`, `:core:data`, `:core:datastore`, `:core:analytics`, `:core:designsystem`, `:core:testing`, `:feature:home` |
| Pattern | `@Observable` view model, `EffectChannel`, `Binding.udf`, `AdaptiveTabStyle` | StateFlow + Channel effects, Hilt, Navigation 3 |
| Tests | Swift Testing + layout matrix (swift-snapshot-testing) | JUnit + Turbine + layout matrix (Roborazzi) |
| Contracts | `L10n`, `Localizable.xcstrings`, `InfoPlist.xcstrings`, `AnalyticsEvent` generated by `contracts-sync` | `strings.xml`, `AnalyticsEvent.kt` generated by `contracts-sync` |
| CI | `.github/workflows/ios.yml` | `.github/workflows/android.yml` |

`FeatureHome` / `:feature:home` is a **sample**: the first slice renames or replaces it.

## Step 0: Preconditions (report each, stop on a blocker)

- **The Phase 1 gate has passed:** `analysis/HANDOFF.md` is *accepted* (the analysis handoff in a migration, the product
  handoff for a new app, guideline 15).
- **`ios/` and `android/` are empty or missing.** A cloned empty repo (only `.git`, README, LICENSE) is fine. If either
  holds a project, stop: this playbook only creates new projects.
- **`PROJECT.md` § Identity is filled in:** app name, bundle ID / applicationId, min OS on both platforms (ADR-0004),
  and the phone orientation policy (§ Working agreements).
  - **Migration, platform already shipped:** the IDs must equal the hybrid app's (guideline 11).
  - **New app, or never shipped:** the IDs are permanent once the first build is uploaded. Confirm them with the product owner.
    A placeholder (`com.example…`) is fine for a test run, never for a store build.
- **Toolchain** (report what's missing; ask before installing anything): `xcodebuild -version` (Xcode with Swift 6.2+),
  `xcodegen --version`, `gradle --version` (only to create the wrapper), a JDK 17+ (Android Studio's JBR works:
  `export JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"`), and the Android SDK (`$ANDROID_HOME`).

## Step 1: Confirm the values (one batched question)

```bash
node tools/scaffold-native.mjs --name "<App name>" --bundle-id <id> [--package <kotlin package>] \
  [--ios-min 17.0] [--min-sdk 26] [--devices universal] [--phone-orientation all|portrait] --dry-run
```

Show the user the values and the file list, then ask once: name, type prefix (`--ident`), bundle ID / applicationId,
Kotlin package, iOS minimum, minSdk, iPhone-only or universal, and phone orientation. Universal and "all" are the ADR-0017
defaults. Portrait-only phones still need every screen to render in landscape on large screens.

## Step 2: Generate

Run the same command without `--dry-run`. Per platform it:
1. copies the template with the tokens filled in;
2. seeds `contracts/strings/en.json` (`app.name`, `common.refresh`) and points `contracts/sync.config.json` at the Android
   package;
3. runs `contracts-sync`, then `xcodegen generate` (iOS) or creates the Gradle wrapper with a pinned checksum (Android);
4. seeds `AGENTS.md` and `CLAUDE.md` from `templates/repo-AGENTS-<platform>.md`, runs `sync-agents-md`, and runs `git init`
   with no commit;
5. writes `.kit-template.json` (kit version and the values used).

## Step 3: Build and test both (run them in parallel)

```bash
# iOS (ios/). The first run records the layout-matrix references and fails once ("No reference was found on disk")
xcodebuild test -project <App>.xcodeproj -scheme <App> -destination 'platform=iOS Simulator,name=<simulator>'
xcodebuild test -project <App>.xcodeproj -scheme <App> -destination 'platform=iOS Simulator,name=<simulator>'   # must pass

# Android (android/)
./gradlew assembleDebug testDebugUnitTest recordRoborazziDebug
./gradlew verifyRoborazziDebug spotlessCheck lintDebug
```

Use the same simulator for recording and CI (`.github/workflows/ios.yml` names it), because snapshots depend on the
device model and OS. Fix any failure before going on (fix-loop limit in `PROJECT.md`). If a fix belongs in the template,
record it in `kit-feedback.md`.

## Step 4: Look at the references

Show the user the six reference images: compact portrait, compact landscape and expanded on each platform
(`ios/Modules/Tests/FeatureHomeTests/__Snapshots__/`, `android/feature/home/src/test/screenshots/`). Check that content
stays readable and centred on the expanded size (ADR-0017).

## Step 5: Run both apps

Show both running before anything else (guideline 04 § Two modes, "Show the app"):
- iOS: open the live simulator panel, build, install and launch the app, then take a screenshot.
- Android: start an emulator, `./gradlew installDebug`, `adb shell am start -n <applicationId>/<package>.MainActivity`, then take a screenshot.
- Optional: `maestro test -e APP_ID=<id> e2e` once a smoke flow exists.

## Step 6: Record and hand over

- `PROJECT.md`: § Current status → *Phase 2 Foundations*. § Identity: the repo URLs if the repos have remotes.
- `decisions/README.md`: the template's choices answer ADR-0005 (Navigation 3), ADR-0006 (XcodeGen) and ADR-0009 (initialiser
  injection / Hilt). Write them as accepted ADRs (`templates/adr.md`), or record a different choice before the first slice.
- Ask before committing. The suggested commit in each repo is `[SETUP] Scaffold from kit <version> templates`, with
  the reference images included. Push and open PRs only if the user asks.
- Next step: the first slice (`/implement-slice SLICE-01`). It replaces the sample Home feature.

## Troubleshooting

- **`requires … compile against version 37 or later`**: newer AndroidX needs a newer `compileSdk`. Raise
  `ProjectConfig.COMPILE_SDK` in `build-logic`. `targetSdk` is separate and changes behaviour, so it needs an ADR.
- **AGP can't download a missing SDK platform (`Connection refused`)**: check the proxy lines in `~/.gradle/gradle.properties`
  (an empty `systemProp.https.proxyHost=` breaks the SDK downloader), or install the platform with Android Studio's
  SDK Manager. Don't edit the user's global Gradle settings yourself.
- **The first iOS run takes several minutes**: it resolves swift-snapshot-testing and does a cold build. Later runs take
  about 20 seconds. Run it in the background and keep working on Android.
- **Android layout captures are blank after the first one**: Robolectric on SDK 36 does this, so the template pins
  screenshot tests to SDK 35 (`src/test/resources/robolectric.properties`). Copy that file into every module that has
  screenshot tests, and set sizes with `RuntimeEnvironment.setQualifiers` inside the test, not with `@Config`.
